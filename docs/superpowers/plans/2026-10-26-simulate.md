# Simulate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Simulate workspace beside the pipeline: studies (metric, period, test surface files) run on demand against the maximum
volume, the envelope and the massing, with results drawn on the 3D view.

**Architecture:** The engine of branch `feature/solar-check` (`solar_check.py`, `check_settings.py`, the Warp mesh kernel) is
ported onto `main`, set to the Tregenza sky with the carving's jittered sub-rays, one sun position per hour, and the project's
context and terrain as blockers. The service stores studies in `project.json` beside the criteria, shares the test surface store
with them, and runs a simulation as a non-pipeline job of the run worker. The app adds a Design | Simulate switch in the header;
Simulate hides the sidebar and puts a floating studies panel, a geometry switch, a legend with a target and a result card over the
3D view.

**Tech Stack:** Python 3.10, NumPy, Warp (mesh BVH), Ladybug, pydantic, FastAPI; React 19, TypeScript, three.js, vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-simulate-design.md`. Engine background: the first build's design on the branch,
`git show feature/solar-check:docs/superpowers/specs/2026-10-22-solar-check-design.md` (sections 3 and 5).

## Global Constraints

- A study never changes a criterion, the shared settings, `inputs_revision`, a criterion record or a stage record.
- Sun hours: one sun position per hour, fixed and hidden. Sky: Tregenza (145 patches), fixed and hidden; sub-rays at the project's
  `rays_per_patch` (1, 4, 9, 16; default 4), hidden; with 1, one ray at each patch centre.
- Test points: sampled at `resolve_grid_step(grid_step, voxel_size)` of the shared settings, in the maximum volume's frame; at most
  2 million points per study.
- Context and terrain block in every geometry; there is no `surroundings` or `check_designs` input.
- Baseline is always the maximum volume. No side by side, no designs, no snapshots, no CSV export, no CLI, no Grasshopper.
- One GPU job at a time: a simulation and a pipeline run never overlap; nothing is queued.
- Copy: plain labels with units, no descriptions, tooltips name the setting; no em dashes; sentence case.
- Test tiers per `docs/testing.md` and the project `CLAUDE.md`; a test over about 1 s gets `@pytest.mark.slow`.
- Front end: after `npm run build`, commit `src/urbansolarcarver/ui_static` (checked by `tests/test_local_web_packaging.py`).
- Commits end with the model's `Co-Authored-By` line. Never `git stash`. Leave untracked `examples/test_inputs/Real_world_examples/` alone.

## Review Focus

1. A test surface file used by a study and by a criterion, when the criterion is deleted (or the file taken out of it): the stored
   file stays for the study, and the reverse. Pinned in Task 5.
2. A study that cannot run (no files, a metric needing the weather file without one, over 2 million points): Run runs the others
   and the panel shows that study's reason. Pinned in Tasks 6 and 9.
3. Editing during a simulation (a study, a criterion, an input) and starting a Design run during one: refused with 409, as during a
   pipeline run. Pinned in Task 6.
4. An envelope or massing that is out of date in Design: Simulate still traces the built mesh; the geometry switch marks it
   "Out of date in Design". Pinned in Tasks 6 and 10.
5. A project from before this change (no `studies` key) opens and runs as before; a deleted study's results folder is removed.
   Pinned in Task 4.

**Interfaces:**
- Consumes: `CheckRequest` (Task 3), `CheckSettings`, `build_check_settings`, `load_solar_check`, `RunWorker`'s `_start_lock`,
  `_active`, `RunConflict`, `RunState`, `RunContext`, `_handler()`.
- Produces:
  - `simulation.study_settings(store, name, study) -> CheckSettings`: the project's shared settings (`north_deg`, `voxel_size`,
    `grid_step`, `time_basis`, `min_altitude`, `ray_length`, `rays_per_patch`) + the study's metric and settings + `epw_path` when

  - `simulation.study_request(store, name, study) -> CheckRequest`: test surface path the study's joined file, `max_volume_path`
    `inputs/joined/max_volume.ply`, `run_folder` `<project>/run`, context and terrain joined files when they exist, `out_dir`
    `simulate/<id>`, the envelope voxel size (`stage_records.envelope_voxel_size`).
  - `simulation.refusal_of(store, name, study) -> str | None`: "Add test surfaces", the missing weather file, or a `ConfigError`'s

  - `StudyState = Literal["current", "out_of_date", "not_run", "refused"]`; `StudyWithState(entry: StudyEntry, state: StudyState, reason: str | None, geometries: list[str])`

  - `RunWorker.start_simulation(name) -> RunState`: 409 `RunConflict` when any run is active; stages `["simulate"]`; a thread that
    runs the studies that can run, in list order, one `CheckRequest` each; events `stage_progress {stage: "simulate", study, done, total}`,
    `issue`, `run_finished {stages: ["simulate"], files: []}`, `run_failed`, `run_cancelled`. It never calls `forget_stages`,
    `record_stages` or `choose_stages`.
