    Pipeline¶

    USC runs in three stages: preprocessing, thresholding, exporting, with massing as an optional fourth that reads the thresholding output like exporting. Each stage writes a manifest, last, after all its other outputs; the next stage reads it, so you can re-run thresholding with different parameters without recomputing scores. Every manifest has a random run_id, new on every run of its stage, and every manifest after preprocessing records the run_id of the manifest it was built from (upstream_run_id); a stage refuses an upstream that was re-run since (StageChainError). Manifests store paths relative to their own folder, so a run folder can be moved or copied. A stage first deletes the manifest and the outputs of its previous run in its folder, so a failed run leaves no manifest.

    run_pipeline() runs the stages needed for what you ask it to produce, in one call. For finer control, call each stage individually.

    from urbansolarcarver import load_config, run_pipeline

# One-shot: preprocessing, thresholding, exporting
result = run_pipeline(load_config("config.yaml"), out_dir="outputs")
print(result.exporting.export_path)

# Decomposed
from urbansolarcarver import preprocessing, thresholding, exporting
from pathlib import Path

cfg = load_config("config.yaml")
pre  = preprocessing(cfg, Path("outputs/preprocessing"))
thr  = thresholding(pre, cfg, Path("outputs/thresholding"))
exp  = exporting(thr, cfg, Path("outputs/exporting"))

    run_pipeline¶

    run_pipeline(config, out_dir, produce=("exporting",), start_from="preprocessing", context=None, after=None) runs start_from and every later stage on the path to the stages in produce. Each stage writes into <out_dir>/<stage>; a stage before start_from is not run, and the next stage reads its output from its folder in out_dir.

    # Floor plates as well as the mesh: preprocessing and thresholding run once
result = run_pipeline(cfg, "outputs", produce=["exporting", "massing"])
print(result.exporting.export_path, result.massing.plates_path)

# Change a threshold setting and reuse the scores already in outputs/preprocessing
cfg = load_config("config.yaml", ["carve_fraction=0.5"])
result = run_pipeline(cfg, "outputs", start_from="thresholding")
assert result.preprocessing is None   # it did not run in this call

    The PipelineResult has one attribute per stage (preprocessing, thresholding, exporting, massing): the Result of a stage that ran in this call, None for the others. Its issues are the conditions noticed during the call (see Issues and run context). A start_from stage that is not on the path to a produced stage raises ValueError; a missing or stale upstream output raises StageChainError. after is given to the thresholding stage as its after (see Thresholding).

    run_chain¶

    run_chain(chain, out_dir=None, produce=("exporting",), start_from="preprocessing", context=None, trace=None, threshold_from=None) runs the criteria of a chain file in order on one voxel grid, then exporting and massing from the last (see Criteria). chain is a path or a ChainConfig from load_chain. Each criterion's stages write to <out_dir>/criteria/<id>/<stage>, and a criterion's thresholding takes the previous criterion's as after. It returns a ChainResult: one PipelineResult per criterion in criteria, then exporting, massing and the issues of the call. With trace (ids of criteria), only those criteria run preprocessing again and the others read their existing preprocessing folder; every criterion from the first traced one on is thresholded again. With threshold_from (an id of the chain), thresholding starts at the earlier of that criterion and the first traced one; the earlier criterion's preprocessing is read as it is. With start_from="thresholding", every criterion is thresholded again unless threshold_from is given: thresholding then starts at that criterion, and the criteria before it keep their thresholding folders, which the criterion decides after (StageChainError naming the folder when one is missing).

    Deciding what to re-run¶

    stages_to_rerun(previous_config, new_config, produce) lists, in pipeline order, the stages that have to run to bring produce up to date after a config change. It compares the settings each stage reads (preprocessing, then thresholding, then each produced leaf stage) and does not look at input files or at which stages exist on disk; that is for the caller to decide. With no previous config it lists every stage produce needs.

    urbansolarcarver.stage_settings ¶

    Per-stage settings projected from the flat configuration.

    Each stage reads only its own settings model; RunOptions holds what does not affect results. effective_values gives the values a stage will apply (defaults resolved, fields its mode does not read left out), so two configs that mean the same compare equal, and :func:stages_to_rerun turns those comparisons into the list of stages to run.

    This module must not import api_core (it pulls in torch).

    stages_to_rerun(previous_config, new_config, produce) ¶

    The stages to run, in pipeline order, to bring produce up to date.

    Compares settings only; whether an input file changed, or whether a stage was ever run, is for the caller to decide.

    • Preprocessing effective values differ: preprocessing, thresholding and the produced leaves (exporting, massing).
    • Else thresholding differs: thresholding and the produced leaves.
    • Else each produced leaf whose own effective values differ.

    Only stages that produce needs are listed, so producing "preprocessing" alone stops the list there. With no previous_config, every stage needed for produce is listed. Raises ValueError for a name that is not in :data:PIPELINE_STAGES.

    Issues and run context¶

    Conditions that are not errors (settings the mode ignores, nothing carved, a footprint that could not be read, ...) are reported as issues: an Issue has the stage it was noticed in, a short code and a message. Each stage Result has issues, and PipelineResult.issues holds those of the whole call. Without a run context the engine also emits each issue as a warning.

    A RunContext passed to run_pipeline collects the issues, calls on_progress(stage, done, total) as a stage advances, and stops the run when cancel() is called (RunCancelled; stages that finished keep their output). report_issue(code, message) records an issue on the active context.

    from urbansolarcarver.run_context import RunContext

context = RunContext(on_progress=lambda stage, done, total: print(stage, done, total))
result = run_pipeline(cfg, "outputs", context=context)
for issue in result.issues:
    print(issue.stage, issue.code, issue.message)

    Preprocessing¶

    Voxelizes the max volume, samples the test surfaces, generates rays toward sky patches (or sun positions, or the tilted-plane direction), traces them through the voxel grid, and writes per-voxel obstruction scores to scores.npy.

    urbansolarcarver.api_core.preprocessing ¶

    PreprocessingResult(out_dir, volume_path, volume_shape, dtype, run_id, device_info='', issues=()) dataclass ¶

    Immutable record returned by :func:preprocessing.

    Carries paths to persisted artifacts and grid metadata so that downstream stages (thresholding, exporting) can locate them without re-computation. volume_path is the scores.npy file. The manifest_path property points to the JSON manifest that the next stage reads; the object also implements __fspath__ (returning that manifest path) so it can be passed directly as a path-like to :func:thresholding.

    preprocessing(cfg, out_dir) ¶

    First stage of the 3-stage envelope pipeline: per-voxel obstruction scoring.

    Converts a maximum-volume mesh and a set of insolation test surfaces into a 3-D scalar field where each voxel carries a score indicating how much it blocks sun or sky from the test surfaces. The steps are:

    1. Voxelization: the maximum-volume mesh is rasterized into a cubic occupancy grid with edge length cfg.voxel_size. This and the next two steps run in a local frame whose origin is the max volume's minimum corner; persisted coordinates are shifted back to world space.
    2. Surface sampling: the test surfaces are point-sampled (spacing cfg.grid_step), giving test points with outward normals. The test surface PLY file may contain several disjoint mesh components (e.g. separate facade panels, a ground plane and a courtyard, or a PV array). All components are sampled and their ray contributions added into a single score grid.

    3. Ray casting: for every test point, rays are cast through the voxel grid according to the configured mode. Each voxel that blocks a ray accumulates a weight that depends on the mode:

    4. time-based: sun-position rays for the configured analysis period; a voxel's score is the protected-surface area it shades times the duration, in m²·h (each sample point stands for ~grid_step² m²).

    5. tilted_plane: one ray per sample point at the plane angle; a non-zero score means the voxel lies on or above at least one plane.
    6. sky-patch modes (irradiance, benefit, daylight, radiative_cooling): rays go toward the sky patches, each patch carrying a mode-specific weight; a voxel's score is the sum of the weights of the rays it blocks times the area each sample point stands for (grid_step²): the solar energy it blocks in kWh (irradiance, benefit), or the sky it hides in m² of fully hidden sky (daylight, radiative_cooling; their weights sum to 1).

    With the optional context (cfg.context_path) and terrain (cfg.terrain_path) meshes, step 1 also removes every voxel column the context overlaps and the voxels below the ground, and in the ray-based modes step 3 drops every ray that hits the context or the terrain before scoring (unless cfg.context_blocks_rays is off). tilted_plane loses the voxels only.

    Thresholding¶

    Converts the score array into a binary carving mask: optional score smoothing, then carve_fraction, head/tail breaks, or a numeric cutoff over the occupied voxels, with carve_above applied through column_postprocessing.carve_above_scores (the cutoff at which carve_above removes each voxel, so that carve_fraction counts what carve_above removes), then the slope limit (max_slope_deg, 75 degrees for the weighted modes; column_postprocessing.limit_column_slope). Writes mask.npy and scores_compared_with_cutoff.npy (float32, the grid shape: the values the cutoff is applied to before the slope limit, which are the carve_above removal cutoffs when carve_above is on and the smoothed scores otherwise); the diagnostics record max_slope_deg, slope_limit_extra_voxels_removed and obstruction_fraction_carved_by_slope_limit.

    With after= (the previous criterion's ThresholdingResult, thresholding folder or manifest.json), the stage decides only among the voxels the previous criterion kept and never keeps a voxel it removed. The manifest records after_manifest and after_run_id, the diagnostics record voxels_at_start, and a previous criterion on another grid, one re-run since, or the previous criterion's own output folder as out_dir raises StageChainError.

    thresholding(volume, cfg, out_dir, after=None) ¶

    thresholding(volume: 'PreprocessingResult', cfg: Union[user_config, str, Path], out_dir: Union[str, Path], after: Union[ThresholdingResult, str, Path, None] = None) -> ThresholdingResult

    thresholding(volume: Union[str, Path], cfg: Union[user_config, str, Path], out_dir: Union[str, Path], after: Union[ThresholdingResult, str, Path, None] = None) -> ThresholdingResult

    Second stage of the 3-stage pipeline: score-to-mask binarisation.

    Loads the per-voxel obstruction scores produced by :func:preprocessing and applies a threshold strategy to produce a Boolean mask indicating which voxels to retain in the final envelope (True = keep, False = carve away).

    For violation_count scores (time-based / tilted_plane modes), only a numeric threshold (cutoff) is accepted and applied directly.

    Threshold strategies (set via cfg.threshold; the config layer normalizes every accepted spelling into a ThresholdSpec, and cfg.resolved_threshold() fills in the mode default when it is unset):

    • cutoff (shorthand: a bare number): a literal cutoff; voxels with score <= value are kept.
    • headtail: head/tail breaks (Jiang 2013). The scores are split at their mean; while the part above the mean (the head) holds at most 40 % of the values, the head is split again at its own mean. The last such mean is the cutoff. Suited to the heavy-tailed score distributions common in urban solar access studies.
    • carve_fraction (default for weighted modes): cumulative-score cutoff. It finds the cutoff at which the removed voxels hold the given fraction of the building's total score mass, counting the voxels that carve_above removes along with them.

    All threshold statistics, retention counts and smoothing use occupied voxels only; the mask is False on empty cells. With carve_above (the default), occupied voxels above a carved run in their column are removed as well. Then, for the score-cutoff methods of the weighted modes (or whenever max_slope_deg is set), columns that rise more steeply than max_slope_deg above their surroundings are cut down (:func:~urbansolarcarver.column_postprocessing.limit_column_slope); this removes some score beyond the fraction, reported as obstruction_fraction_carved_by_slope_limit. mask.npy is the final mask that gets exported.

    After a previous criterion (after): in a chain of criteria on one voxel grid, each criterion decides only among the voxels the previous one kept. The base of this run is then the occupied voxels that the previous criterion's mask.npy keeps, instead of all occupied voxels: smoothing, the threshold statistics, carve_fraction, carve_above and the slope limit all act on those voxels, and the mask is never True where the previous mask is False. Both runs must share the grid (max volume, context, terrain, voxel size and margin); otherwise a StageChainError is raised. When the previous criterion kept no voxel, the mask is empty and the issue nothing_left_to_carve is reported. The manifest then records after_manifest and after_run_id, and the diagnostics after_run_id and voxels_at_start (the voxels this criterion decides about).

    Score smoothing (cfg.score_smoothing):

    Before thresholding, a Gaussian blur can be applied to the continuous score volume to smooth resolution-dependent noise. This produces a cleaner binary mask (and carved mesh) at fine voxel sizes.

    • None (default): auto, 1.1 × voxel_size metres.
    • 0: disabled, no smoothing.
    • Positive float: explicit radius (Gaussian sigma) in metres. Rule of thumb: keep close to voxel_size (1.0–1.2×). Values above 2× voxel_size over-smooth and round features.

    Only applied to weighted-score modes (irradiance, benefit, daylight, radiative_cooling). Violation-count modes (time-based, tilted_plane) are unaffected.

    To tune carve_fraction against a performance target, compare obstruction_fraction_carved in diagnostics/diagnostic.json across runs.

    exporting(threshold_manifest, cfg, out_dir) ¶

    exporting(threshold_manifest: 'ThresholdingResult', cfg: Union[user_config, str, Path], out_dir: Union[str, Path]) -> ExportingResult

    exporting(threshold_manifest: Union[str, Path], cfg: Union[user_config, str, Path], out_dir: Union[str, Path]) -> ExportingResult

    Third stage of the 3-stage pipeline: mesh extraction from the binary mask.

    Loads the Boolean voxel mask produced by :func:thresholding and the occupancy grid persisted during :func:preprocessing, combines them (logical AND), and converts the resulting carved voxel field into a triangle mesh suitable for downstream CAD / BIM / visualisation workflows.

    Mesh extraction proceeds through :func:~urbansolarcarver.meshing.finalize_mesh, which supports two strategies (selected by cfg.apply_smoothing):

    • cubic (apply_smoothing=False, default): a 3x3x3 neighbour filter first drops isolated voxels, then the exposed faces of the occupied voxels are emitted; fast, produces the classic voxel look.
    • smoothed (apply_smoothing=True): the binary field is converted to a signed-distance field, smoothed, and iso-surfaced with Marching Cubes, then polished with cfg.smooth_iters Taubin passes (0-6).

    On both paths, connected voxel clusters smaller than cfg.min_voxels and mesh fragments with fewer than cfg.min_face_count faces are removed. The mesh uses the voxel size and origin recorded by preprocessing; the config's voxel_size is not read.

    Massing¶

    Builds stacked floor plates that follow the footprint from the carving mask (see Floor-plate massing).     massing(threshold_manifest, cfg, out_dir) ¶

    Fourth stage: floor plates that follow the footprint, from the carved envelope.

    Floors are ground_floor_height then floor_height tall, counted from the lowest point of the maximum volume. The footprint (the plan projection of the maximum volume that preprocessing saved as footprint.json, not the mesh named in cfg) is split into faces, one per facade, and each face into square modules of min_plate_dimension, cut along its facade and in depth behind it. A module is built on a floor when it stays in the maximum volume over the floor's full height, at most plate_tolerance of its volume lies outside the carved envelope, and (with plate_stacking: supported) it is built on the floor below. See :mod:urbansolarcarver.floor_plates.
