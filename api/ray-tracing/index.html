    Ray Tracing¶

    Ray generation and voxel traversal for the carving pipeline, in two modules. The main kernels use a DDA (Digital Differential Analyzer) that steps each ray through the voxel grid and adds to a per-voxel volume in a single pass.

    ray_tracing.py builds and traces the rays:

    • trace_and_score_dda: traces a batch of rays and adds each ray's weight to every voxel it crosses (weighted modes). Runs on CUDA or on Warp's CPU backend.
    • trace_and_count_dda: the same traversal, adding a count of 1 per ray (time-based and tilted_plane).
    • trace_point_access_dda: stops each ray at the first occupied voxel and adds its weight to its test point's accessible or blocked weight (test_point_access_evaluation).
    • follow_mass_behind_skin_dda: the skin rule, which keeps a test surface's skin voxels with the mass behind them.
    • generate_sky_patch_rays / generate_sun_rays: expand sample points × directions into flat ray arrays (origins + directions), keeping only directions the surface faces.
    • auto_batch_size: picks a ray batch size from the free GPU memory, to avoid out-of-memory errors on large scenes.

    warp_kernels.py sets up Warp and holds every Warp kernel of the package (the DDA kernels above and the parity voxelizer that voxelization.voxelize_solid_warp launches), so Warp compiles and caches them as one module:

    • dda_backend_available: whether the Warp DDA backend can run on a device.
    • require_dda_backend: raises WarpBackendUnavailableError, naming the reason, when it cannot. Ray tracing has no other backend; every carver calls this first.
    • warmup_kernels: precompiles the Warp kernels (urbansolarcarver warmup).

    Rays are processed in batches. With ray_batch_size: 0 (the default) the batch size comes from auto_batch_size; set a positive value to fix it.

    urbansolarcarver.ray_tracing ¶

    UrbanSolarCarver: ray generation and voxel grid traversal¶

    This module builds rays (sample point to sky patch, or sample point to sun, keeping only directions the surface faces) and traces them through the voxel grid for the carving pipeline.

    Rays are traced with the DDA (digital differential analyzer, Amanatides & Woo 1987) Warp kernels of :mod:warp_kernels, launched here, on CUDA or on Warp's CPU backend. The fused wrappers (:func:trace_and_score_dda, :func:trace_and_count_dda) add each ray's weight or a count of 1 directly into a per-voxel volume, so no list of hits is stored; :func:trace_point_access_dda adds each ray's weight to its test point when it reaches no occupied voxel. :func:mesh_blocks_rays tests rays against the context and terrain meshes (a Warp BVH) instead of the grid. In the sky-patch modes the wrappers can take a :class:SkySubRays: each ray then stands for several jittered sub-rays over its patch, whose directions the kernels compute, so the sub-rays are never stored (:func:mesh_blocks_sky_sub_rays is their context test). There is no other tracer: when Warp cannot run, the carvers raise WarpBackendUnavailableError (see :func:warp_kernels.require_dda_backend).

    The coordinate conventions are those of :mod:warp_kernels.

    SkySubRays ¶

    Bases: NamedTuple

    How the kernels split each sky-patch ray into jittered sub-rays.

    Ray r becomes the side**2 threads r * side**2 + k, each tracing the direction :func:sky_patches.sub_ray_directions gives and carrying 1 / side**2 of the patch weight; the sub-rays the surface does not face are skipped. Pass None instead to trace each ray's own direction (the patch centre).

    follow_mass_behind_skin_dda(min_corner, scale, resolution, origins, ray_dirs, point_ids, surface_normals, occupancy, values, ray_length, patch_ids=None, sub_rays=None, skip=None) ¶

    Return values with every own-skin voxel raised to the value of the voxel behind it.

    A voxel the source surface's plane passes through is that surface's skin. When the skin voxel and the voxel behind it are both occupied, the skin belongs to the mass behind the surface: its own rays do not count it, but it must not outlast that mass. So each skin voxel a ray visits takes the maximum of its value and the value of the voxel behind it (counts: removed when the mass behind is removed; scores: never below the mass behind).

    The voxel behind a skin voxel is found by stepping from the skin voxel's centre one cell length at a time against the surface normal, up to three steps, until the voxel containing the stepped point lies wholly behind the plane.

    generate_sky_patch_rays(pts, norms, patch_dirs, device, facing_margin=0.0) ¶

    One ray per (sample point, sky patch) pair whose patch the surface faces.

    A ray is kept only where dot(normal, patch direction) > -facing_margin: with the default 0, where the surface faces the patch centre; with sky sub-rays, :func:sky_patches.patch_facing_margin keeps every patch the surface faces in part.

    The rays are ordered by patch, then by sample point, so the threads that run together trace one direction from neighbouring points and visit nearby voxels; on the GPU this keeps the voxel arrays in the cache (on the District example, tracing took a quarter of the time it took with the rays ordered by point).

    auto_batch_size(device, *, vram_fraction=0.6, fallback=300000) ¶

    Choose a ray batch size from the free GPU memory.

    The budget is vram_fraction of free VRAM (video memory). The fused DDA kernels accumulate into the voxel grid and keep no hit lists, so a batch only adds its slice of the ray inputs: 96 bytes per ray (see the comment in the code). The result is at least 10,000 and at most 5,000,000 rays.

    Returns fallback on CPU or if VRAM cannot be queried.

    		 0.6
    fallback int

    		 300000

    Recommended ray batch size.

    urbansolarcarver.warp_kernels ¶

    UrbanSolarCarver: Warp setup and kernels¶

    Initializes NVIDIA Warp, tells whether its exact DDA backend can run on a device (:func:dda_backend_available), precompiles the kernels (:func:warmup_kernels), and defines every Warp kernel of the package:

    • the DDA traversal (digital differential analyzer, Amanatides & Woo 1987): one thread per ray, stepping from voxel to voxel and visiting every voxel the ray crosses exactly once, with fused kernels that add each ray's weight or a count of 1 directly into a per-voxel volume, the first-hit kernel of the test point access evaluation and the kernel of the skin rule; in the sky-patch modes a thread can trace one of several jittered sub-rays of a sky patch, whose direction it computes itself (see the note above _lowbias32);
    • the parity voxelizer used by :func:voxelization.voxelize_solid_warp;
    • the ground heights of a terrain mesh and the voxel centres on the context's surface, used by :mod:context_geometry, and the any-hit test of rays against the context and terrain meshes (:func:ray_tracing.mesh_blocks_rays);
    • the mesh visibility kernel of the sun and sky check (:mod:solar_check), which traces rays against a triangle mesh's BVH (wp.Mesh) instead of the voxel grid.

    All kernels live in this one module on purpose: Warp compiles a Python module as one unit and caches it on disk by module, so :func:warmup_kernels compiles them all at once. The kernels exist only when Warp imports and initializes (_warp_available). Their launch wrappers are in :mod:ray_tracing, :mod:voxelization and :mod:solar_check.

    References

    Amanatides, J. & Woo, A. (1987). "A Fast Voxel Traversal Algorithm for Ray Tracing." Eurographics '87, pp. 3-10.

    Coordinate conventions
    • World to grid: grid_idx = floor((world_pt - origin) / cell_size)
    • Cell size: cell_size = scale / resolution (meters per voxel)
    • Flat index: x * resolution**2 + y * resolution + z (row-major, C order)
    • floor maps a point to the voxel that contains it; rounding would shift every index by half a voxel.

    warmup_kernels(device=None) ¶

    Compile (or load from the on-disk cache) this module's Warp kernels for device now instead of on first use.

    Warp compiles all kernels in a module on the first launch. This costs roughly 3-10 s once per machine, device and code version; afterwards the compiled binaries load from Warp's disk cache in milliseconds. Calling this during installation (setup_env.py), at daemon startup, or via usc warmup moves that cost to a moment where the user already expects to wait, so the first carving run is not slowed by it.

    Parameters:

    Name Type Description Default
    device device | str | None

    Target device. None resolves like cfg.device='auto': CUDA when available, else the Warp CPU backend.

    		 None

    Returns:

    Type Description
    bool

    True if the kernels are ready on the device (compiled or cached); False if Warp is unavailable or compilation failed. When only the precompilation failed, the kernels compile on first use instead.

    dda_backend_available(device) ¶

    True if the Warp DDA backend can run on device: Warp initialised and, for the CPU, Warp's CPU backend can compile kernels.

    require_dda_backend(device) ¶

    Raise WarpBackendUnavailableError unless the Warp DDA backend can run on device. Ray tracing has no other backend; the error says why Warp cannot run and how to repair the installation.

    mesh_visible_weight_kernel(mesh_id, has_mesh, mesh_tolerance, clip_id, has_clip, clip_tolerance, blocking_id, has_blocking, blocking_tolerance, points, normals, directions, values, use_cosine, sub_side, patch_cells, patch_ids, d_start, d_end, origin_offset, min_hit, max_t, out) ¶

    Add the value of every direction in [d_start, d_end) that a test point faces and sees past the mesh and the blocking meshes.

    One thread per test point. With sub_side > 1, direction k is sub-ray k % sub_side**2 of patch patch_ids[k], drawn for test point i as the carving draws it (_sky_sub_ray_direction, see the note above _lowbias32). A ray is blocked where it is inside the mesh's solid and, with a clip solid, inside the clip solid too: the mesh then counts only where it overlaps the clip (a carved envelope that bulges past the maximum volume blocks nothing outside it). The blocking meshes block wherever the ray meets them. Inside and outside follow the faces' orientation (closed meshes with outward normals); a start inside is judged by :func:_check_start, with each mesh's own tolerance.
